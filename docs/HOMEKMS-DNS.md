# HomeKMS DNS 自动发现：兼容性与验收边界

## 支持范围

自动发现默认关闭。启用服务及自动发现并保存应用后，HomeKMS 通过**系统 dnsmasq** 在本地 DNS 域发布 KMS SRV 记录。兼容的客户端需要使用能够返回该记录的 DNS 解析路径，并查询相同的本地域；仅将客户端 DNS 地址设为路由器，不足以保证自动发现成功。

HomeKMS 不自动刷新、重启或修改其他 DNS 服务。系统 dnsmasq 中的记录更新，不代表 DNS 代理或独立 DNS 实例已同步。记录新增、端口变更和关闭/停止后的记录移除均需检查实际客户端解析路径。DNS 缓存也可能使旧答案暂时保留。

若客户端查询经过 DNS 代理或独立 DNS 实例，管理员须按该服务支持的方式同步刷新配置，确认其能返回当前 SRV 记录及目标主机地址。不能同步或无法确认时，请在客户端**手动指定 HomeKMS 地址和端口**，不要依赖自动发现。手动指定地址只绕过服务发现，不代表网络连通性或产品激活已验证。

## 已定位的 PassWall2 场景

在已排查的 1.2 环境中，PassWall2 启动时将系统 dnsmasq 配置复制到 `/tmp/etc/passwall2/acl/acl_default_dnsmasq.conf`，独立实例监听 2004 端口，nft 规则将客户端的 53 端口查询转发至该实例。因此后续仅更新或重载系统 dnsmasq，不会自动更新已经生成的代理配置副本。启用之前复制的配置可能缺少新记录，关闭之前复制的配置也可能残留旧记录。

这描述的是已定位环境，不是所有 PassWall2 版本、ACL 模式或 DNS 实现的通用行为。不得据此宣称所有 DNS 代理都会丢弃本地规则，也不得宣称 HomeKMS 开箱适配所有 DNS。同步操作由管理员明确执行；HomeKMS 不静默重启 PassWall2，也不直接修改其临时生成文件。

## 分层验收

1. **本地组件测试**：执行 `node --test luci-app-homekms/tests/*.test.mjs`。检查自动发现选项保留默认关闭、系统 dnsmasq 范围、代理/独立实例同步要求、手动地址回退和不自动刷新其他 DNS 服务的说明；校验英文消息与中文 PO/POT 一致。此测试使用 LuCI 视图测试桩，不是路由器 DNS 或真实客户端端到端测试。
2. **系统 dnsmasq 基线**：单独查询实际系统实例的 SRV 记录，验证发布、端口更新和撤销；同时核对记录目标的地址解析。这只能证明系统实例，不能证明代理实例或客户端路径。
3. **实际客户端 DNS 路径**：确认代理是否运行、实际监听端口及重定向规则。分别查询系统实例、代理/独立实例及客户端配置的 DNS 地址，比较 SRV 与目标地址答案。必要时分别检查 A/AAAA 响应，不能用单个 IPv4 答案代表所有查询均成功。
4. **同步后复验**：在管理员明确授权并通过代理自身支持的方式同步后，重复新增/变更/撤销检查，考虑缓存 TTL。不得直接编辑代理临时文件，也不得为测试擅自启动或重启代理。
5. **客户端发现与激活**：只有真实兼容客户端沿实际 DNS 路径取得记录并连接到正确地址和端口，才能认定该环境的自动发现有效；发现成功、端口连通与产品激活应分别记录，不得互相替代。

没有执行相应层级的测试时，应标为未验证，不能由前端文字断言或系统 dnsmasq 测试推导为所有 DNS 兼容。
